# ERC-8241 disclosures: draft and check

[ERC-8241](https://ethereum-magicians.org/t/erc-8241-protocol-control-disclosure/28343) (Protocol Control Disclosure, draft) standardises what a protocol declares about who controls it: components, the nodes that hold power, the powers themselves and the edges between nodes. The draft says it "standardizes disclosure, not truth" and that independent verification remains necessary. `ownerwatch disclosure` is that verification, for the parts chain state can settle.

```bash
ownerwatch disclosure draft 0xPOOL 0xPROVIDER 0xACL --rpc https://mainnet.gateway.tenderly.co --name "My protocol" > disclosure.json
ownerwatch disclosure check disclosure.json --rpc https://mainnet.gateway.tenderly.co [--block N] [--json] [--logs-rpc URL] [--no-roles-from-logs]
```

`check` exits 1 on any mismatch or undisclosed power, so it can gate CI the same way the ownerwatch Action's drift check does.

## The JSON form

The draft defines records, not a file format, so this is a direct JSON rendering of the core records. Field names follow the draft's wording.

| ERC-8241 record | JSON | Fields |
|---|---|---|
| ProtocolMetadata | `protocol` | `name`, `chainId`, `manifestHash`, optional `manifestURI` |
| DisclosureScope | `scope` | `components` (component ids), `assets`, `exclusions`, `assumptions` |
| Component | `components[]` | `componentId`, `address`, `nodeId`, `type`, `upgradeable`, `implementation`, `adminNodeId` |
| GraphNode | `nodes[]` | `nodeId`, `type` (`EOA`, `MULTISIG`, `TIMELOCK`, `CONTRACT`, `GOVERNOR`), `address`, optional `threshold`, `controllerCount`, `delay` |
| PowerDescriptor | `powers[]` | `powerId`, `kind`, `enabled`, `target` (a component id), `controllerNodeId`, `role` (for `ROLE`), optional `threshold`, `controllerCount`, `delay` |
| GraphEdge | `edges[]` | `edgeId`, `kind`, `from`, `to`, `direct` |
| Freshness | `nonce` | a monotonic disclosure nonce |

`manifestHash` is keccak256 of the canonical JSON (sorted keys, no whitespace) with `protocol.manifestHash` itself left out, so anyone can recompute it from the file.

## What `check` settles

Every read is pinned to one block (latest, or `--block`), and the report records the block number and hash, so two people checking the same file at the same block get the same answer.

| Record | Checked against chain state |
|---|---|
| `protocol` | `manifestHash` matches the file; `chainId` matches the RPC |
| node | type (EOA, Safe, timelock, contract); a Safe's threshold and owner count; a timelock's delay (OpenZeppelin, Compound-style, Solady, Ownable-delay and Aave PayloadsController timelocks) |
| component | code at the address; upgradeable or not; implementation; upgrade admin (ERC-1967 slot, factory-stored admins, Aave-style immutable admins) |
| power | `UPGRADE` (the component's upgrade admin), `OWNERSHIP` (`owner()`), `ROLE` (`hasRole`, by role name or hash), plus declared threshold, controller count and delay against the controller node |
| edge | `OWNER_OF`, `UPGRADE_ADMIN_OF` between address-bound nodes |

Each record is `ok`, `mismatch` or `unverifiable`. Power kinds chain state cannot settle (for example an oracle update whose authority lives in off-chain configuration) are reported `unverifiable`, never `ok`.

**Completeness.** After checking what is declared, `check` lists control it observes on the declared components that no power declares: an upgrade admin, an `owner()`, or an AccessControl role holder. Role holders are found by replaying `RoleGranted`/`RoleRevoked` logs from each component's creation block up to the pinned block, and every replayed holder is confirmed with `hasRole` at that block; roles are compared by hash and named from the contract's own bytes32 getters in its verified ABI (`POOL_ADMIN_ROLE()` and the like). This answers "were other control paths disclosed?" for the declared components. It cannot see components that are not declared, or authority that is not expressed in contract state. `--no-roles-from-logs` skips the replay and only tests common roles on addresses the disclosure or the chain already names, which misses most protocol-specific roles.

## Examples

`examples/erc-8241/` has a disclosure drafted from Aave V3's Ethereum core (Pool, PoolAddressesProvider, ACLManager) at block 26298094, with the role replay: 37 nodes, 25 role holders on the ACLManager (pool admin, emergency admin, risk admins, flash borrowers) and 22 controller edges. It checks clean: 89 records ok. Two edited copies show what the checker catches:

- `aave-v3-stale.json` claims a 2-day delay on both timelocks in the graph (each is 1 day) and a non-upgradeable Pool: 3 mismatches.
- `aave-v3-omission.json` leaves out the ACLManager's DEFAULT_ADMIN_ROLE (Executor Lvl 1) and EMERGENCY_ADMIN_ROLE (the Protocol Guardian Safe): 2 undisclosed powers.

The workflow `.github/workflows/erc8241-examples.yml` regenerates and checks them. Results depend on the block: re-draft against the current block before relying on them.
